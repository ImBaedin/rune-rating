P0

Routing and errors

Frontend + backend

Invalid RSNs crash into a raw Convex stack trace.

A malformed player route or rating query can throw from domain RSN normalization inside a Convex query. The browser then shows the default TanStack error boundary and internal server stack details.

Evidence and fix

Reproduced: /compare/thisnameiswaytoolong/Hey%20Jase and /rating?rsn=thisnameiswaytoolong.

Code refs: apps/web/src/routes/compare/$leftRsn/$rightRsn.tsx:9, apps/web/src/routes/rating.tsx:4, packages/backend/convex/lib/players.ts:6, packages/domain/src/rsn.ts:3.

Fix: validate and normalize route/search params at the route boundary before any Convex call, render a friendly invalid-player state, and add a route/root errorComponent that hides internal stack traces.

P0

Provider safety

Convex action

Collection detail refresh bypasses the main cooldown pipeline.

Opening Collections can auto-call a public action that loops arbitrary RSNs, calls RuneProfile using the API key, and writes collection rows. The only repeat guard is a per-client useRef, so new sessions can repeat the provider call.

Evidence and fix

Code refs: apps/web/src/pages/CollectionsPage.tsx:105, apps/web/src/pages/CollectionsPage.tsx:121, packages/backend/convex/runeProfile.ts:678, packages/backend/convex/runeProfile.ts:697.

Contrast: the normal refresh path in packages/backend/convex/refresh.ts has argument caps, leases, cooldowns, and scheduled background work.

Fix: route collection detail refresh through a server-side claim/cooldown/backoff flow, cap RSNs to the comparison pair, validate RSNs before provider work, and consider making collection detail refresh an explicit action instead of automatic page-load behavior.

P1

Production SSR

Frontend

Production HTML can render mock player cards for real URLs.

The topbar route state can show the requested RSNs while the server-rendered player cards still fall back to Northstar and Moss Giant. That creates a visible flash risk and poor crawler/share-preview content.

Evidence and fix

Reproduced: production /compare/Lynx%20Titan/Hey%20Jase returned route RSNs in the topbar but mock player cards in SSR HTML.

Code refs: apps/web/src/App.tsx:73, apps/web/src/App.tsx:741, apps/web/src/App.tsx:760, apps/web/src/App.tsx:3968, apps/web/src/mockData.ts:18.

Fix: remove mock player fallback from production comparison shells. Pass route RSNs into loading cards or move mock data behind story/prototype-only routes.

P1

Config hygiene

Convex

RuneProfile credentials are read from untyped process.env.

The generated Convex guidelines for this project require environment variables to be declared in convex.config.ts and accessed through generated typed env bindings.

Evidence and fix

Code refs: packages/backend/convex/sources/runeProfile.ts:27, packages/backend/convex/runeProfile.ts:696, packages/backend/convex/_generated/ai/guidelines.md.

Fix: add a Convex env declaration for RUNEPROFILE_API_KEY, regenerate Convex files, and replace direct process.env reads with generated env access.

P1

Accessibility

Mobile drawer

The mobile drawer overlays the page but leaves the page interactive to assistive tech.

When the drawer is open, the sidebar and scrim appear, but the underlying main content remains in the accessibility tree. Keyboard and screen-reader users can still traverse content behind the overlay.

Evidence and fix

Code refs: apps/web/src/App.tsx:652, apps/web/src/App.tsx:718.

Fix: treat the mobile sidebar as a modal drawer: focus the drawer on open, return focus on close, close on Escape, and set the page root/main to inert or aria-hidden while open.

P1

Accessibility

Forms and controls

Several inputs and selects remove outlines without consistent replacement focus styles.

The app has highly customized controls, but several CSS rules set outline: 0 and rely on visual styling that is not consistently tied to :focus-visible or :focus-within.

Evidence and fix

Code refs: apps/web/src/styles.css:302, apps/web/src/styles.css:1651, apps/web/src/styles.css:4556, apps/web/src/components/comparison-ui.css:206, apps/web/src/pages/BossingPage.css:43.

Fix: add visible :focus-visible and wrapper :focus-within treatments for topbar RSN fields, shared search fields, rating form inputs, and selects.

Reference: this aligns with the Vercel Web Interface Guidelines focus-state guidance linked in the footer.

P2

SSR routing

Frontend

The root route returns blank SSR HTML and redirects only after hydration.

/ returns a 200 with scripts and styles but no meaningful page content until client JavaScript runs. That makes first paint, crawler behavior, and no-JS fallback weaker.

Evidence and fix

Code refs: apps/web/src/routes/index.tsx:9, apps/web/src/App.tsx:909, apps/web/src/App.tsx:925.

Fix: make root a real server-rendered default comparison page or use a server-side redirect to the default comparison URL.

P2

Interaction polish

Frontend

Visible buttons imply actions that do not exist yet.

The player kebab buttons and generated highlight rows look interactive. They use button semantics, cursor affordances, and icons, but do not open menus or navigate anywhere.

Evidence and fix

Code refs: apps/web/src/App.tsx:3998, apps/web/src/App.tsx:4724.

Fix: either remove these controls before launch or wire them to real behavior: player actions menu, source profile links, or deep links into the relevant comparison section.

P2

Navigation semantics

Frontend

Route navigation is implemented with buttons instead of links.

Sidebar items and page navigation call navigate() from buttons. The URL updates, but users lose native link affordances such as open in new tab, copy link, and expected screen-reader link semantics.

Evidence and fix

Code refs: apps/web/src/App.tsx:979, apps/web/src/App.tsx:4550.

Fix: replace route-changing buttons with TanStack Router Link components and keep buttons for local UI actions only.

P2

Forms

Frontend

Search and RSN inputs are missing useful form metadata.

Several inputs have labels but no name, non-auth search fields lack consistent autocomplete and spellcheck choices, and placeholders are used as examples rather than clean prompt text.

Evidence and fix

Code refs: apps/web/src/App.tsx:3852, apps/web/src/RatingPage.tsx:363, apps/web/src/components/comparison-ui.tsx:220.

Fix: add stable field names, set autocomplete="off" for RSN/search fields, disable spellcheck for usernames and code-like item searches, and keep visible labels.

P2

Charts

Frontend

Responsive charts warn about zero or negative dimensions on mobile.

Combat Achievements and Minigames emitted Recharts warnings during mobile route smoke tests. The charts eventually render, but the warning suggests a layout race or collapsing container.

Evidence and fix

Console warning: The width(-1) and height(-1) of chart should be greater than 0.

Code refs: apps/web/src/pages/CombatAchievementsPage.tsx:1004, apps/web/src/pages/MinigamesPage.tsx:223.

Fix: give chart wrappers stable numeric height/aspect constraints or delay ResponsiveContainer rendering until the container has measurable dimensions.

P2

Mobile readability

Collections

Collection chart labels are hard to read on narrow screens.

Long category names wrap or visually collide in the collection page-gap chart. This is most visible for Treasure Trail categories on a 390px viewport.

Evidence and fix

Code refs: apps/web/src/pages/CollectionsPage.tsx:402, apps/web/src/pages/CollectionsPage.css:377.

Fix: use a mobile-specific ranked list, abbreviate axis labels, or provide wider label columns with deterministic wrapping.

P2

Test coverage

Web

The web package has no real automated tests or route smoke suite.

Repository tests pass, but the web script is a placeholder. The invalid-RSN crash, Recharts warnings, and mobile drawer accessibility issue are exactly the sort of launch bugs a small browser suite would catch.

Evidence and fix

Code ref: apps/web/package.json:14 has echo 'No tests configured for visual prototype'.

Fix: add a Bun-driven Playwright smoke suite for root redirect, all route tabs, invalid RSN handling, mobile drawer behavior, and production SSR content.

P2

Frontend structure

Code quality

App.tsx is carrying too many product surfaces.

The objective comparison extraction is complete: shell navigation, topbar search, source health chips, route helpers, lookup history, player identity, comparison context, route page components, and common number/date formatters now live under apps/web/src/features/comparison. The category pages consume the new context and formatters. The main app file now carries the comparison shell only, and comparison route pages are split into focused route modules.

Evidence and fix

Code refs: apps/web/src/App.tsx is now 461 lines; apps/web/src/features/comparison/pages.tsx is a 6-line route-facing barrel; apps/web/src/features/comparison/page-modules/overview.tsx, skills.tsx, xpTimelineRoute.tsx, efficiency.tsx, activity.tsx, and shared.tsx now own the comparison route surfaces and shared page helpers. context.tsx, navigation.ts, formatters.ts, lookupHistory.ts, playerIdentity.ts, and components/* own the extracted comparison shell logic. Category pages import useComparisonShell from the feature context now. The only remaining route import from App.tsx is the comparison shell route.

Remaining review: promote stable primitives like source chips, empty states, loading cards, search fields, stat rows, and panel headers into a real shared UI package or local component folder when the design system boundary is clearer.

Data transformations: pull repeated formatting, mapping, grouping, sorting, and chart-shaping logic out of page components into named hooks or utilities. Keep provider-specific response handling inside the SDK/backend boundary so web components only consume canonical RuneRating models.

P2

Backend structure

Convex

Backend provider modules are large and contain some brittle collection limits.

wiseOldMan.ts, refresh.ts, and runeProfile.ts combine public APIs, cache claims, provider calls, replacement writes, and read models. Some rich-data reads/deletes also use broad collect() or fixed take() caps that could silently truncate as provider catalogs grow.

Evidence and fix

Code refs: packages/backend/convex/wiseOldMan.ts is 1,734 lines; packages/backend/convex/refresh.ts is 830 lines; packages/backend/convex/runeProfile.ts is 736 lines.

Data refs: runeProfile.getCategory collects canonical items, and collection-log replacement/comparison uses fixed caps like take(2500) and take(500).

Fix: split by source capability, centralize cache claim/release helpers, and convert rich-data reads/deletes to explicit bounded queries, pagination, or revision-based cleanup.
